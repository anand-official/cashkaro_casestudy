02 / Platform reality

Shared tools do not mean shared distribution.

Surface Verified basis What this proposal still needs
ChatGPT Apps SDK describes MCP-based apps and a submission flow Accepted commerce use, account linking, tool availability and useful invocation
Claude Integrations connects external services Applicable connector review, supported UI and a tested purchase-intent handoff
Gemini UCP and Cart API supports merchant cart transfer A consumer Gemini entry point for this non-merchant router is not established; a developer API implementation is not equivalent
Share / CashKaro-owned surfaces User intentionally transfers a product link Product/variant resolution, permitted exact-item deep link and channel attribution tests

OpenAI developer terms do not guarantee placement or publication. The current plugin guidelines constrain commerce and data handling. Physical-product use is not blanket approval of this affiliate model. Request only purchase-specific context, not full chat history. Read these documents again before actual submission to a platform.

Google's announcement includes Wallet-related benefits and merchant offers, which limits the novelty of generic effective-price assistance. The announced US-first availability is not evidence of a live India integration. Its Cart API moves a cart into merchant systems and is distinct from payment. CashKaro needs approved referral routing, not a copied cart.

Platform discovery test: can an authorized user reach the skill at a concrete purchase decision, with acceptable effort and predictable disclosure? Observe each host separately. A neutral simulated interface is not proof that any host supports its placement.

03 / Market context

Adoption, influence and transactions have different denominators.

BCG, 2 January 2026 reports rising GenAI use for product research across categories. Its stated quantitative methodology covers more than 9,000 respondents per wave across nine countries, including India; the supplementary qualitative purchase research is US-based. This supports investigating Indian adoption, not assigning the pooled findings to Indian CashKaro users. No verified India-only AI-origin transaction share was established here.

Bain / Flipkart, 2025 estimates over 270 million Indian online shoppers and roughly $60 billion e-retail GMV in 2024, with growth of 10–12% that year. Those are market estimates, not the number of existing CashKaro users we can reach. Its quick-commerce discussion is also a reminder that frequent shopping may happen in unsupported journeys.

YouTube India, 10 October 2025 reports over 200 million logged-in users with shopping-related searches in July 2025 and existing creator affiliate commerce. Research is already distributed; creator attribution must be respected. Neither searching nor watching establishes an order.

The mentor's “13%” figure is not used for sizing. Bread Financial, 3 November 2025 describes planned holiday gift inspiration via ChatGPT among surveyed shoppers. It is not an India transaction statistic. PayPal, 25 November 2025 announced Perplexity purchasing for US users with a limited 50%-back promotion capped at $50. We did not verify a 13% Perplexity discount. A subsidized historical promotion is not sustainable demand evidence.

Research needed for our denominator: sample existing CashKaro accounts, ask about actual recent purchases and tools used, link answers to pre-period order data with consent, and assess nonresponse. Report AI-assisted research, concrete AI purchase intent, supported merchant eligibility and successful host access separately.

04 / Affiliate economics

Explicit user value is necessary. Permission is still separate.

In its 21 January 2026 statement, Awin describes its Honey investigation, policy breaches and a remediation path. This is the network's account and enforcement position, not a court judgment establishing every public allegation. Awin's rules are not automatically CashKaro's contracts.

Chrome's Affiliate Ads policy requires a related user action and a direct, transparent benefit when an extension adds affiliate links or cookies. It is an extension policy, not permission for an AI app. It is relevant precedent for a clear design boundary.

The proposed router must disclose CashKaro's commission role, require deliberate activation, follow network/merchant stand-down rules, and never invisibly rewrite cookies or change a recommendation for commission. A user accepting Cashback may still change the referral credited with the sale. Do not claim that a button eliminates attribution conflict.

Commercial question Required validation
Is this traffic source permitted? Partnerships obtains written scope for each merchant and host/source class
Is another affiliate already involved? Pass known source provenance; apply agreed stand-down handling; unknown provenance is a dependency
Does the merchant gain demand? Separate retailer total-order experiment if partner data and consent permit; do not infer from CashKaro orders
Can CashKaro retain margin? Actual commission minus funded benefit, reversals, serving, support and host fees
Would a host compete directly? Monitor native incentives and willingness to expose third-party rewards

The V1 makes no merchant-switching or conversion-uplift claim. Either can become a separate later experiment. No production contract has been obtained for this assignment.

For the extension question in the PDF, the earlier 11 September snapshot of Statcounter India reported 34.97% desktop web usage for August 2026. This is not shopping share and excludes native-app activity. It is a dated inherited source check, not newly measured data. If desktop shopping intensity equals other web activity and native apps hold 60% of orders, a deliberately hypothetical proxy is 0.3497 × 0.4 ≈ 14% desktop orders. Different intensity/app assumptions change it substantially. Replace with cohort channel data before prioritizing an extension.

All route surfaces need effective-dated merchant/domain/path mappings with an operations owner, expiry, refresh and a kill switch. An agent would additionally need product data and relevance infrastructure. Neither RAG nor a model can manufacture current retailer eligibility. The selected Skill avoids CashKaro inference calls rather than claiming an invented per-query model cost.
