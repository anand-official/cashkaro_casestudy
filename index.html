Product decision · Existing-user habit

CashKaro shouldn't need to be remembered.

Existing users naturally start shopping inside retailer apps. Instead of predicting when they might shop—or asking them to restart their journey—we make CashKaro available when shopping context already exists.

01 · Start with the behavior

The leak looks like forgetfulness. The deeper issue is journey position.

The user's destination is the retailer, not the affiliate layer. CashKaro currently asks the user to remember an extra step before a habit that already exists.

Today

User wants a product → opens retailer → browses → checks native offers → pays. CashKaro is outside the active journey and must be recalled.

NeedRetailerBrowsePay

Opportunity

Let the user keep the retailer habit. Attach CashKaro's value to that context, with explicit activation and minimal disruption.

02 · We challenged the obvious answer

“Send a reminder” fails when the underlying signal is incomplete.

CashKaro observes routed purchases, not the direct purchases it is trying to recover. A heavy leaker can therefore look like an infrequent shopper.

Predict → remind

Historical routed orders → infer timing → send push → hope shopping intent exists.

Incomplete historyPredictionInterruption

Observe context → activate

Supported retailer is already open → surface value → user activates CashKaro → shopping continues.

Observed contextValueExplicit activation
Don't predict the shopping moment if you can observe that shopping has already started.
03 · The extension insight

The browser extension solves the right behavioral problem on the wrong surface.

Its strength is not the popup. It is that CashKaro becomes available after shopping begins. In a mobile/app-heavy journey, the analogous intervention belongs on Android.

Product thesis

CashKaro does not need to become the place where shopping starts. It can become the savings layer around destinations users already choose.

  • Android-first
  • Retailer-aware, not product-aware
  • Explicit activation every session
  • No screen reading / Accessibility
  • No AI required for V1
04 · CashKaro Shopping Companion

Earn the right to be present once. Earn the right to participate in every purchase.

The experience is deliberately lightweight: prove value, earn permission, surface only when useful, activate explicitly, then close the trust loop with tracking proof.

05 · Prove business impact, not engagement

Randomize the offer. Measure the cohort.

Comparing people who voluntarily enable the feature against those who don't would select for cashback enthusiasts. The causal test is an intention-to-treat experiment.

Control

Normal CashKaro experience. No Shopping Companion setup offer.

Treatment

Eligible existing users are offered Companion setup. Refusal, abandonment and non-use remain part of treatment impact.

06 · What could kill it

A good prototype is not evidence that the product should ship.

GATE 01

Permission adoption

Do enough existing users complete the Android setup for cohort-level impact?

GATE 02

Partner approval

Do retailer / affiliate agreements allow this post-entry activation mechanism?

GATE 03

Causal uplift

Does the randomized cohort generate incremental tracked orders?

GATE 04

Economics & reach

After all multipliers, is the effect material and commercially sustainable?

The hardest question: did we create value—or only recapture attribution?
