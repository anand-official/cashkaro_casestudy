## Shared tools do not mean shared distribution.

| Surface | Verified basis | What this proposal still needs |
| --- | --- | --- |
| ChatGPT | [Apps SDK](https://help.openai.com/en/articles/12515353-build-with-the-apps-sdk) describes MCP-based apps and a submission flow | Accepted commerce use, account linking, tool availability and useful invocation |
| Claude | [Integrations](https://claude.com/blog/integrations) connects external services | Applicable connector review, supported UI and a tested purchase-intent handoff |
| Gemini | [UCP and Cart API](https://developers.google.com/merchant/ucp/guides/overview/cart-overview) supports merchant cart transfer | A consumer Gemini entry point for this non-merchant router is not established; a developer API implementation is not equivalent |
| Share / CashKaro-owned surfaces | User intentionally transfers a product link | Product/variant resolution, permitted exact-item deep link and channel attribution tests |

[OpenAI developer terms](https://openai.com/policies/developer-apps-terms/) do not guarantee placement or publication. The [current plugin guidelines](https://developers.openai.com/plugins/app-guidelines) constrain commerce and data handling. Physical-product use is not blanket approval of this affiliate model. Request only purchase-specific context, not full chat history. Read these documents again before actual submission to a platform.

Google's announcement includes Wallet-related benefits and merchant offers, which limits the novelty of generic effective-price assistance. The announced US-first availability is not evidence of a live India integration. Its Cart API moves a cart into merchant systems and is distinct from payment. CashKaro needs approved referral routing, not a copied cart.

**Platform discovery test:** can an authorized user reach the skill at a concrete purchase decision, with acceptable effort and predictable disclosure? Observe each host separately. A neutral simulated interface is not proof that any host supports its placement.
</section>

<section class="case-section" id="india">
<p class="section-label">03 / Market context</p>

## Adoption, influence and transactions have different denominators.

[BCG, 2 January 2026](https://www.bcg.com/publications/2026/consumers-trust-ai-to-buy-better-brands-must-adapt) reports rising GenAI use for product research across categories. Its stated quantitative methodology covers more than 9,000 respondents per wave across nine countries, including India; the supplementary qualitative purchase research is US-based. This supports investigating Indian adoption, not assigning the pooled findings to Indian CashKaro users. No verified India-only AI-origin transaction share was established here.

[Bain / Flipkart, 2025](https://www.bain.com/insights/how-india-shops-online-2025/) estimates over 270 million Indian online shoppers and roughly $60 billion e-retail GMV in 2024, with growth of 10–12% that year. Those are market estimates, not the number of existing CashKaro users we can reach. Its quick-commerce discussion is also a reminder that frequent shopping may happen in unsupported journeys.

[YouTube India, 10 October 2025](https://blog.google/intl/en-in/products/platforms/fueling-the-next-era-of-creator-led-shopping-experiences-in-india/) reports over 200 million logged-in users with shopping-related searches in July 2025 and existing creator affiliate commerce. Research is already distributed; creator attribution must be respected. Neither searching nor watching establishes an order.

**The mentor's “13%” figure is not used for sizing.** [Bread Financial, 3 November 2025](https://newsroom.breadfinancial.com/holiday-2025-chat-gpt-quicktake) describes planned holiday gift inspiration via ChatGPT among surveyed shoppers. It is not an India transaction statistic. [PayPal, 25 November 2025](https://newsroom.paypal-corp.com/2025-11-PayPal-and-Perplexity-Launch-Instant-Buy) announced Perplexity purchasing for US users with a limited 50%-back promotion capped at $50. We did not verify a 13% Perplexity discount. A subsidized historical promotion is not sustainable demand evidence.

**Research needed for our denominator:** sample existing CashKaro accounts, ask about actual recent purchases and tools used, link answers to pre-period order data with consent, and assess nonresponse. Report AI-assisted research, concrete AI purchase intent, supported merchant eligibility and successful host access separately.
</section>

<section class="case-section" id="attribution">
<p class="section-label">04 / Affiliate economics</p>

## Explicit user value is necessary. Permission is still separate.

In its [21 January 2026 statement](https://www.awin.com/gb/news-and-events/post/awin-group-statement-honey-investigation), Awin describes its Honey investigation, policy breaches and a remediation path. This is the network's account and enforcement position, not a court judgment establishing every public allegation. Awin's rules are not automatically CashKaro's contracts.

[Chrome's Affiliate Ads policy](https://developer.chrome.com/docs/webstore/program-policies/affiliate-ads) requires a related user action and a direct, transparent benefit when an extension adds affiliate links or cookies. It is an extension policy, not permission for an AI app. It is relevant precedent for a clear design boundary.

The proposed router must disclose CashKaro's commission role, require deliberate activation, follow network/merchant stand-down rules, and never invisibly rewrite cookies or change a recommendation for commission. A user accepting Cashback may still change the referral credited with the sale. Do not claim that a button eliminates attribution conflict.

| Commercial question | Required validation |
| --- | --- |
| Is this traffic source permitted? | Partnerships obtains written scope for each merchant and host/source class |
| Is another affiliate already involved? | Pass known source provenance; apply agreed stand-down handling; unknown provenance is a dependency |
| Does the merchant gain demand? | Separate retailer total-order experiment if partner data and consent permit; do not infer from CashKaro orders |
| Can CashKaro retain margin? | Actual commission minus funded benefit, reversals, serving, support and host fees |
| Would a host compete directly? | Monitor native incentives and willingness to expose third-party rewards |

The V1 makes no merchant-switching or conversion-uplift claim. Either can become a separate later experiment. No production contract has been obtained for this assignment.
</section>

<section class="case-section" id="alternatives">
<p class="section-label">05 / Trade-off detail</p>

## Universal describes reuse, not universal availability.

| Option | Recall / user fit | Reach and frequency | Feasibility / effort / data | Commercial, privacy and platform trade-off | Time to useful validation |
| --- | --- | --- | --- | --- | --- |
| Universal Skill | Potentially low repeated recall at explicit intent | Unknown AI overlap; category mix critical | Medium-high integration uncertainty; small route registry, auth, typed benefits | Host-controlled discovery; partner permission; no broad browsing collection | Host + partner spike before outcome test |
| Share | Explicit and user-controlled but recall remains | Potentially broad link-capable surfaces | Medium; URL/variant handoff and app/web fallback | Exact context not guaranteed; same affiliate rules | Quick usability test plus approved-route test |
| Overlay | Retailer context without recall | Android opt-ins; app sessions not orders | High permission/OEM burden; package registry | Intrusive; late-stage recapture; usage privacy | Permission and commercial spike first |
| Extension | In-page opportunity | Desktop and supported browsers; installation needed | Medium; domain registry and source updates | Stand-down rules, consent and browser policy | Limited browser experiment |
| Reminders | Depends on signal quality | Owned reachable users, uncertain intent | Low-medium; cadence/click signals incomplete | Fatigue; false positives; service consent | Trigger audit before a reminder trial |
| Order Check | Trust/recovery problem fit | Already-routed users across categories | Medium; record continuity and current baseline audit | Lower host dependence; delayed growth mechanism | Existing journey usability check |
| Owned discovery | Adds a new starting destination | Habit/distribution unproven; phones infrequent | High; licensed catalog, prices, ranking and retrieval | Competes with established research platforms | Demand test before agent engineering |
| Widget | Fewer entry taps | Opt-in home-screen users | Low; retailer shortcuts and freshness | Still remembered first; low differentiation | Small orders-based test |

For the extension question in the PDF, the earlier 11 September snapshot of [Statcounter India](https://gs.statcounter.com/platform-market-share/desktop-mobile-tablet/india) reported 34.97% desktop web usage for August 2026. This is not shopping share and excludes native-app activity. It is a dated inherited source check, not newly measured data. If desktop shopping intensity equals other web activity and native apps hold 60% of orders, a deliberately hypothetical proxy is 0.3497 × 0.4 ≈ 14% desktop orders. Different intensity/app assumptions change it substantially. Replace with cohort channel data before prioritizing an extension.

All route surfaces need effective-dated merchant/domain/path mappings with an operations owner, expiry, refresh and a kill switch. An agent would additionally need product data and relevance infrastructure. Neither RAG nor a model can manufacture current retailer eligibility. The selected Skill avoids CashKaro inference calls rather than claiming an invented per-query model cost.
</section>
